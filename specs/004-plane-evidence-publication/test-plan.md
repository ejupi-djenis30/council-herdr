# COU-9 acceptance and evidence plan

General suites run on Node 20 and 24 for Windows, Linux and macOS. A native proof records OS and architecture, installer/tree/digests, operator and worker role separation, tested local filesystem, Plane profile without credentials, accepted visibility/role fixture, status/POST counts and evidence limits. Report simulated transport/filesystem faults, real local filesystem/process tests and installed native/live provider proofs individually.

| ID | Case | Required observations |
| --- | --- | --- |
| A01 | Baseline and offline | Legacy COU-2/8 item projects empty; reads do not migrate; all existing review actions continue; offline and restart preserve the original link, operation and receipt. |
| A02 | Scoped Plane adapter | v1 current-user/project/scoped item and scoped human ID; UUID mismatch, archived, deleted, draft, unauthenticated, wrong role, renamed/replaced pins, wrong membership, redirect, accidental v2 routes and TLS failures. Fixture denies all mismatches before Start. Live gate uses dedicated principal and test item. |
| A03 | Local one-link rules | Two local projects and two remote projects share display names and human key/sequence. Wrong, late and stale responses never link the other scope. Multi-process same-target confirm converges; different target CAS fails. Installed publisher state is operator-private. Exercise installation replacement at the same machine/project/item, delayed old-generation show/open responses, stable verified identity during provider outage and null/absent/invalid identity. Reject caller-supplied IDs and prove reads neither enroll nor touch credentials. Use the reader-identity vectors in the canonical examples. |
| A04 | Exact evidence and display | Strict URL grammar, allowlist, repo ID/public verification, exact base repo and exact full SHA/URL, provider outage or redirect, typed COU-8 state and integrity, actual preview bytes, independent link/publish confirmation. Closing and reopening keep their local meaning. |
| A05 | Authority | Public UI and MCP cannot publish; unauthorized principal, unattended input, replaced or stale trusted session, CLI flags/env and public integration keys yield no POST. Native test distinct real principals and deny worker access to profile/code, key, journal, operator input and outbox. |
| A06 | Payload and field ownership | Record request routed only to the canonical fixed path and captured semantic body equals approved bytes. Track planning field snapshots, credentials confinement, comment audience, exact reply shape and normalization; search test logs, diagnostics, UI, journal and outputs for canaries from prompt/transcript, local path and credential. |
| A07 | Crash/replay/parallel send | Real separate processes for claim, injected storage and transport failures around intent, approve, Start, POST and receipt. No send when durable fence cannot be established; no replay after fence; expired/cancelled/stale preview and changed principal deny Start. Demonstrate truthful states across restart. |
| A08 | Reconcile | 2xx malformed, lost acknowledgement, committed/no commit, edited/deleted/wrong author/marker, second-page match, duplicate, empty, torn/malformed pages and traversal attempt. Only unique positively validated scoped detail commits receipt, with zero reconcile POSTs. |
| A09 | Operator control before Start | Offline/restart without fresh confirm, stale COU-8 or changed pins, monotonic expiry, work changes after last local read, new revision while original delivery uncertain, cancelled/superseded and read-only original receipt. |
| A10 | Roadmap repetition test | Run at least the first ten checked-in vectors, plus listed edge vectors. Capture post attempts and visible comments separately. At most one comment per logical publication, exactly one link, zero planning field changes. Cross-check correct receipt source and author. |
| A11 | Windows installation and platform restrictions | Package smoke and ordinary commands exercised on installed engine without a credential. Disabled default verified. Gate trust separately on dedicated Windows ARM64 profile. Crash/restart and directory durability must be proven there before allowing live Start. |
| A12 | Workspace interaction | Correct focus and bidirectional navigation, precise console handoff, narrow-width text, unresolved actions, stale asynchronous events, history recovery, accessibility labels/announcements on an installed host. Distinguish view fixtures and actual tool/runtime behavior. |
| A13 | Provider deployment proof | Approved dedicated Plane item only. Positive INTERNAL create/readback, 401/403 behavior and denied scope, author fields, safe normalization, two pages with cursor, read-only lost-ack recovery, no metadata-field changes, and intermediary without retry. Verify using the integration credential under the accepted boundary. |

Initial backend may use a scripted HTTP Plane/GitHub fixture with fault switches and real staged filesystem, separate from the installed issuer. Start with [canonical examples](contracts/examples.json). Each repetition starts from a separate fixture journal and issue, so the intended link and comment counts can be checked per case. Foreign-marker setup is external fixture noise and excluded from the Council-created comment count. Do not sabotage or populate operational Plane items for tests.
