# Research: Durable Council work items

| Decision | Evidence and rationale | Alternatives considered |
| --- | --- | --- |
| Reuse Team's existing asynchronous delegation | [Team integration](../../lib/team.js) resolves names, uses per-role permissions and delegates to [JobManager](../../lib/jobs.js). Job sessions already preserve deadline and transport evidence. | A second job manager would duplicate lifecycle and side effects. |
| Atomically publish a single dispatch intent | [Store helpers](../../herdr/mods/council/runtime/store-files.mjs) already publish complete numbered records with atomic hard links on a single volume. Callers can observe which writer won. | Check-then-dispatch races. Replaying a launch through a stale lock can resend after a crash. |
| Persist linkage before launch, project the job outcome when reading | A process can exit before JobManager reserves its directory or after launch but before the reply. The underlying job can appear or finish later. Keeping job state authoritative also preserves recovery actions and avoids dual writers. | Mirroring the job into a second status record can go stale. Treating an absent job as a draft can result in a duplicate delivery. |
| Use the project-machine CLI for Desktop | [Machine engine](../../herdr/mods/council/machine-engine.js) already resolves and runs the CLI on the selected machine with a chosen working directory. CLI and MCP share one application entry point. | Local-only file reads or a second Desktop backend would diverge on paired machines or on job validation. |
| Use one canonical local folder | [Workspace scope](../../herdr/mods/council/runtime/activity.mjs) already resolves the focused project. Canonical filesystem paths unify aliases. Distinct Git worktree roots remain distinct. | Automatically mapping a project to the primary Git checkout would cross deliberate workspace boundaries. |
| Preserve original capture provenance | [Job result](../../lib/jobs.js) returns saved output, turn and any `captureScope`. Existing [worker capture](../../lib/job-worker.js) owns those semantics. A lead reviews the work-item criteria using that evidence. | A separate work-item result file or extra approval state adds authority or duplicates the capture. |
