# Acceptance and evidence plan

| Gate | Evidence | Requirements |
| --- | --- | --- |
| A01 — Definition | Create twice with equivalent normalized input, conflicting content, role removed after first create, invalid ID/fields, no directory before mutation, ordered criteria, independent projects and path aliases. Prove a second process reads identical saved metadata. | FR-001–003, FR-009 |
| A02 — Store | Concurrent creation of the same and different definitions. Malformed, oversized, partial, symlinked and missing events. Unsupported publication or denied write. Unaffected rows remain discoverable. | FR-001–002, FR-006, FR-009–010 |
| A03 — Shared APIs | Exercise all four commands and tools with envelope assertions. MCP explicit project guard, CLI absolute override, paths with spaces and UTF-8, unknown keys, correct exit code and MCP error flag. Package smoke checks actual published file layout and MCP tool advertisement. | FR-003, FR-009 |
| A04 — Real store and fake transport | Assert one async Team call, exact criteria order and normalized content, profile/permission, binding, actual saved deadline and no extra mode. Assert unavailable role returns an error without a new intent. | FR-004–005 |
| A05 — Claim race | Launch two independent processes for one item, even when different timeouts race. Validate the single persisted intent, one invocation of the transport seam and zero launch/send from the loser. | FR-005, FR-010 |
| A06 — Interruption | Fault after intent publication before job reservation, during job reservation, and after the durable job/dispatch before the client reply. Also test acknowledgement uncertain, worker stopped, deadline exceeded and possible late completion. Restart the client. Inspect the same session and deadline with zero new launches/sends. | FR-005–006, FR-010 |
| A07 — Link integrity | Foreign mode, role, ID or session; missing job; corrupt job; path escape; inconsistent result/delivery; dispatch error sidecar; terminal screen stored as a file. Readable attention or verified evidence as applicable. Compare job bytes before and after read-only paths. | FR-006–007, FR-009 |
| A08 — Projection | Test every state in the data model, including blocked/awaiting input and late completed result. Confirm list never probes Herdr, and show uses only bounded existing observation. A valid capture reopens as Result ready and asks for review. | FR-006–008 |
| B01 — Workspace controls | Scope selection to focus/pin, role loading, saved criteria, state label, Next action, read error and no-roles behaviors. Use wire fixtures to render result with the correct source. | FR-003, FR-007–008 |
| B02 — Workspace recovery | Capture actual project-engine argv and machine. Change focus before a response. Simulate lost create/delegate receipts, check read-only recovery, keep original ID and target, and deep-link only a verified job. | FR-003, FR-005–008 |
| I01 — Platform matrix | Existing GitHub Actions matrix, Windows/macOS/Linux on Node 20 and 24, plus packaged MCP smoke. Record run and commit links, including any failed or unavailable cells. | FR-009, SC-004 |
| I02 — Live transport | In an isolated project and bounded Herdr space, use a plain fixture program at the configured Team agent entry point. Exercise real launch/delivery/wait/capture and reopen from a new process. Count attempts and confirm owned-only cleanup. Record command, platform, hc version and original job/session evidence. | SC-001–004 |
| I03 — Real agent | With an explicit agent assignment, repeat the quickstart with a real configured agent using a bounded harmless criteria-specific task. Validate its output against the criteria and reopen in the UI. Record the tested revision and reviewed evidence separately from I02. | SC-001–004 |
| I04 — Native UI | With PRs A and B installed on the target machine, open the actual Herdr Workspace. Create, delegate once, change focus, return after completion, inspect result and linked Delegations detail. Record machine/site and build version. Remote or alternate platform checks are claimed only where exercised. | FR-003, FR-007–009 |

Mock transport and filesystem-backed contract tests are regressions. I02 proves the live transport exercised by its fixture. I03 requires task-specific output from the actual assigned agent. The doctor checks tool availability and configuration. These evidence categories have separate entries in the review.

Run `npm test`, `node bin/council.js doctor`, the existing package smoke and `herdr-app check herdr/mods/council` on the relevant revision. In Herdr, follow `hc --skill`, use `hc run --bg` for long commands, then inspect `hc wait` and the result. Track owned fixture terminal addresses. Preserve uncertain or incomplete terminals. Never use unrelated or borrowed terminal cleanup as part of the test.
