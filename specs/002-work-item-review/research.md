# Research: Triage and review Council work items

| Decision | Repository evidence and rationale | Alternative considered |
| --- | --- | --- |
| Preserve the first two slots | [WorkItemStore](../../herdr/mods/council/runtime/work-item-store.mjs) and [COU-2](../001-work-items/data-model.md) reserve definition and initial intent. A marker in the same intent slot gives atomic precedence to a concurrent legacy dispatch or activation. The marker makes old delegates fail closed. | A separate activation flag leaves a gap in which an old writer can claim slot 2 after a newer dispatch. A bulk rewrite makes every item vulnerable to interrupted upgrades. |
| Keep execution, lifecycle and formal verdict observable | [JobManager](../../lib/jobs.js) owns delivery, deadline and capture. Old clients already consume a four-state execution model. Add a lifecycle projection and keep job outcomes separate. | A single combined state would hide rejected reviews behind a completed worker or break existing clients. |
| Persist frozen content before the review event | [Store helpers](../../herdr/mods/council/runtime/store-files.mjs) publish full bytes atomically without replacement. A digest-addressed snapshot keeps original review evidence even if a later result or report changes. | A live result path alone can point to changed bytes. Embedding a large capture in each event wastes space and makes list expensive. |
| Explicit local lead acceptance and a sticky formal requirement | [Owner decision](../../docs/owner-brief.md#owner-decision-screen-evidence-cannot-authorize) reserves formal authorization for direct ballots from completed voters. [Formal APIs](../../lib/formal-rounds.js) and [discussion validation](../../herdr/mods/council/runtime/discussion.mjs) already expose the requisite authority. Local explicit acceptance records the lead's decision. | Automatically closing after a worker completes or a ballot report appears removes the lead decision. Allowing a formal review to downgrade after rejection loses its meaning. |
| Keep blockers descriptive | The [roadmap](../../docs/herdr-project-product-brief.md#roadmap-and-acceptance) asks for local links and attention filters. Record actual linked item status without introducing a project transaction across independent journals. | Implicit dependency scheduling or a global acyclic graph requires cross-item coordination and changes the role of a blocker. |
| Preserve the project-machine path | The [COU-4 controller](../../herdr/mods/council/work-item-actions.js) freezes scope and recovers replies through reads. Keep the same transport and hold the intended scope across focus changes and machine boundaries. | Local file reads from Desktop can select a different project from the engine. |
