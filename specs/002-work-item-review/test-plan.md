# Acceptance matrix

| Gate | Evidence required | Requirements |
| --- | --- | --- |
| A01 — Legacy projection | Pre-feature drafts and valid saved starting, completed, failed and uncertain attempts keep IDs, original deadlines, evidence and original role. No read writes files. A corrupted intent stays visible. A valid old result can be frozen and closed only after review. | FR-001–002, FR-004–005, FR-009 |
| A02 — Writer upgrade | Use two processes and immutable slots to race legacy dispatch against v2 activation. If legacy wins, v2 sees one original attempt and stale revision. If activation wins, the legacy binary refuses to launch. Crash after marker publication, reopen at the same revision and verify zero sends. Test binary rollback semantics in an isolated copy. | FR-002–003, FR-009 |
| A03 — Journal integrity | Race triage, close, reopen and dispatch operations on the same expected revision. Check winner receipt and stale replay, changed request reuse, typed conflicts, publication loss, invalid UTF-8, gaps, wrong prior digest, invalid schema and ignored temporary files. Verify sound prefix, healthy neighbours and honest errors on filesystems that cannot publish. | FR-002–003, FR-007, FR-009 |
| A04 — Project and triage | Ten items, repeated IDs in adjacent real worktrees, same-directory alias, spaces and Unicode, seeded roles and blockers. Verify filters, sorting, evidence scoping, no cross-project writes, removal of a linked item's data and blocker cycles. Verify editing the execution definition cannot change a committed attempt's brief. | FR-001–004, FR-010 |
| A05 — Explicit operator decision | A completed job still needs review. Freeze output, check digest, byte equality, ordered criteria, role and label. Persist findings and dissent. Close only with actor, reason, revision and current evidence token. Mutate evidence between preview/approval, deny closure and retain review. | FR-004–005, FR-007 |
| A06 — Formal negatives | Provide one rejected, one provisional, one unknown or stale report, a forged success marker, wrong binding line, wrong round, malicious link path, missing ballots, invalid ballot, and invalid or unavailable proposal bytes. Preserve observed verdicts. None may close. Verify the formal policy cannot be downgraded after a return or reopen. | FR-004–007, FR-011 |
| A07 — Formal positive | Use real persisted direct ballot and completed-round protocol fixtures generated through existing rules. Approve only the exact verified proposal binding and matching authoritative verdict. Require the operator acceptance after authorization. Check late or torn retally and stale evidence rejection. Compare original formal artifacts before and after reads. | FR-004–007, FR-011 |
| A08 — Reopen and rework | Close and reopen with exact decision and digest, inspect old history and capture after restarting, and dispatch a second cycle exactly once. Return a rejected or provisional review with next action and role. Verify journal lineage, new attempt ID/deadline, no invalidation, and eventual access to both cycles. | FR-003, FR-007–009 |
| A09 — Execution and ambiguity | Lose the reservation acknowledgement before JobManager, after job reservation, and after send. Record actual job evidence and zero extra starts across later create/list/show/delegate/history. Verify corrupt job binding, stale callback, removed role and unconfirmed original intent. | FR-002–003, FR-008–009 |
| A10 — Surfaces and packages | Exercise actual CLI and MCP stdio, typed schema and errors/exit codes, project guard, v1 compatibility, history pages and published fixtures. Assert older helper manifests still load. Check the package includes lifecycle runtime, existing Work items modules and icon license. Run an isolated installed engine. | FR-001–011 |
| B01 — Workspace filters and source | Show ten items, valid and broken rows, filters, editing rules, capture provenance, distinct policy/verdict, findings and history. Assert correct project/engine arguments, safe deep-links and different role lists. | FR-001, FR-004–008, FR-010 |
| B02 — Workspace recovery | Lose mutation replies, submit stale forms, change project or machine while async reads or writes are in flight, try an older engine, reopen a saved decision. Verify read-only receipt and detail requests, fresh confirmation, no unversioned fallback and one observed mutation. | FR-003–005, FR-008–010 |
| I01 — Combined build | Windows/macOS/Linux on Node 20 and 24 in CI. Run focused work-item and existing workflows, doctor and packaging. Verify exact tested revisions, original compatibility and isolated install. | FR-009–011, SC-005 |
| I02 — Native with fixture | In an isolated Herdr space, use a bounded deterministic Node participant over actual `hc`. Create/triage, delegate, freeze, inspect source, close, restart Workspace and reopen in the original project. Link to both attempts, record counts, and verify owned-only terminal cleanup. Include rejected and provisional records supplied by existing formal fixtures. | SC-001–005 |
| I03 — Release evidence | COU-7 tracks a separately authorized real-agent task and per-target native Desktop, keyboard/focus and accessibility evidence. Record tested commit, OS, architecture, Node, hc, Desktop and harness. Test the existing adopted-terminal path separately from managed Team work. | FR-011, SC-005 |

A regression with real files but fake transport is a regression. I02 exercises the live Herdr transport and native UI only on the stated host. An agent result requires the actual assigned harness and task-specific evidence. An installer smoke or static mod check establishes packaging/load only.

Run `npm test`, `node bin/council.js doctor`, package smoke and `herdr-app check herdr/mods/council` at the relevant revision. In Herdr follow `hc --skill` and inspect the own worker's state, turn, delivery and wait reason. An exit code alone cannot mark a job complete. Never dismiss a borrowed or incomplete participant. Record discovered limitations beside each check.
