# Workspace and native operator UI

## Workspace, CLI and MCP metadata

The Workspace pilot panel reads the current verified project scope and displays reference, direction, recognized project and run, verified requester and recipient labels, fixed operation and route labels, status, expiry, receipt ID when present, failure category and next action. Optional public read surfaces `secret-handoff list --json`, `secret-handoff show --id <request-id> --json` and MCP `council_secret_handoff_list` / `council_secret_handoff_show` use the same projection if shipped. No public surface offers value-bearing arguments or an approval/consumption command. The native enrolled fixture protocol is separate. A scope change clears selection, discards pending refresh responses and cannot retarget an old click.

**Open native consent** resolves the installed absolute bridge executable from the supported package and calls local `herdr.exec` with a verb and one exact non-authorizing reference as argv entries. No shell, caller path, dynamic destination, environment override or remote execution is accepted. Stdout allows one bounded versioned typed envelope, stderr is empty in normal operation and never parsed as product evidence. Unknown output, launch failure or timeout produces a bounded unavailable or refresh message. The bridge does not advance a state, and app exit/timeout does not establish consent, delivery or failure. The pinned v0.1.16 exec surface may carry app environment; the bridge reads no configuration from it. Trusted child launch supplies an explicit environment allowlist and closed or typed stdio, with no inherited handles except explicitly required ones.

The bridge stages only the selected reference. On the local console the operator switches to the dedicated operator Windows identity through the Windows sign-in flow, then opens the administrator-provisioned **Council Synthetic Handoff** entry from that account. The operator can select the staged ID from an authenticated inbox or enter its exact reference there. Workspace offers these instructions and can be closed while the operator acts. A mod-rendered copy, notification, request ID, URL or apparent native window in the participant's session cannot approve. A Windows identity can be reauthenticated through Windows sign-in when locked or stale. A session that cannot be verified as the designated active local console is unavailable. A broker service runs headless, and the installed operator UI is a separate peer in the operator session.

## Native prompt and reveal

The installed UI uses the pinned broker connection and a dedicated local operator desktop whose ACL and session isolate it from the fixture profile. Verify the UI image and its immutable installation; the broker accepts decisions only from the measured operator peer and matched operator SID/logon/session. The human recognizes the surface by entering it from the dedicated Windows session and installed entry, then verifies the reviewed prompt. A static title, toast, icon, visual imitation or role name carries no authority.

Render **Synthetic pilot**, verified project, run ID, generation, initiator identity and role and stable ID, recipient identity and stable ID, operation, purpose, exact fixed destination, single use, local and UTC absolute expiry, and current decision. Show operator and participant separately, including the enrolled participant for direction B. Role labels are paired with authoritative identifiers. Native review refreshes the tuple from the broker at every relevant action. Invalidated scope disables approval and Show, with the failure category and next step. Opening the prompt, switching focus and closing the window are passive. Keyboard focus is visible. Buttons are labeled for direction and distinguish **Approve use**, **Accept offer**, **Deny**, **Cancel request**, **Revoke grant** and **Show once** where appropriate. An operator cannot act as a participant. In A, show the fixed, broker-provided label of the exact selected synthetic entry alongside its scope before **Approve use**. Changing the selection requires a new prompt context and explicit approval. A stale selection cannot commit and requires refreshed review, while replacement after consent invalidates the existing grant and needs a new request. Private entry IDs and versions remain within the broker. **Show once** is available only after **Accept offer** and a fresh check of the designated active session.

The broker owns a one-shot authenticated render channel separate from the metadata UI. Use a protected native surface with no selectable/copyable value, window title echo, accessibility value/child serialization or plaintext diagnostic rendering. Verify the isolation before unsealing. Close, lock, loss of console/focus or peer invalidation immediately clears the surface. Impose a maximum 15-second display lifetime. The control may announce that a value was displayed, and describe the action and security consequence before activation. It exposes accessible metadata, buttons, focus and typed status without assistive export of cleartext. Record any untested native assistive technology or usability limitation. No promise of screen reader access to the raw value is made by this pilot.

The render receipt records broker observation of a trusted display acknowledgement only. It cannot prove human attention. Unsupported native protection leaves Show unavailable. Disable clipboard, screen sharing and crash reporting for the isolated pilot surfaces. Capture affinity, where supported, adds defense in depth. Evidence includes no screenshot or screen recording while the value is visible.

## Status and next actions

Show distinct pending, approved or accepted, denied, cancelled, expired, invalidated, revoked, in progress, completed and delivery-uncertain states. For uncertainty show the stable operation/receipt reference and **Check existing receipt**. This action never sends or shows again. For a closed reveal with no receipt, explain that it may already have been shown and a fresh authorized ceremony is needed for a distinct value. Revocation retains prior outcome and displays that it stops future use and cannot recall a dispatch or visible value. The fake provides no provider revocation or rotation action. Normal work continues when the pilot is unavailable.
