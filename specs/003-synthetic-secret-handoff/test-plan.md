# Acceptance matrix and evidence plan

Source is the CEO-accepted COU-6 matrix and decision named in [the specification](spec.md). U is the authenticated local operator, A the enrolled participant, R the actual managed run, and G the enrolled generation. Execute the matrix in one disposable local project on the declared native Windows ARM64 package. Use a controlled clock and independent counters for adapter invocation, fake effect and render. All variants use distinct IDs and internally generated canaries. Counters reset per case, with same-ID continuity retained within retries.

Contract keys below are [Authority](contracts/authority.md), [Effects](contracts/requests-and-effects.md), [UI](contracts/operator-ui.md) and [Custody](data-model.md). Each row needs executed evidence, with the expected assertions below and any platform gaps explicitly flagged.

## Direction A entry selection checks

Run the following as A01 variants and observe the normal participant-request path in A02. Use two distinct internally generated canaries, one for each active synthetic entry. Verify that the fixture initially distinguishes them. Provision the two expected canaries to the fixed fake through the authorized private fixture channel. Its in-process comparator compares the attempted value with both and emits boolean results plus independent invocation and effect counts. Neither the comparator nor the evidence writer emits either value, a fingerprint, a label, or a private selector/version.

| Variant | Expected result |
| --- | --- |
| Approve the first entry with both active. Attempt to supply the other selector as a participant parameter before invoking normally. | The malformed request has zero counts. Normal invocation has one effect, matches the approved entry and does not match the other. Repeat on a fresh grant approving the second entry and observe the opposite match. |
| Replace the selected version while the native prompt is open but unapproved. | The stale approval context is rejected. No grant or effect exists. The operator must verify the refreshed selection before approving. |
| Retire or replace the approved version before Claim, then independently between Claim and Start. In separate runs remove the binding or substitute a different valid encrypted entry envelope under the selected record before each fence. | No adapter invocation, fake effect or reveal. The original request is unavailable and cannot be retried with a changed selection. A distinct request and fresh native consent for the replacement permit its value once. |
| Commit Start with the old binding before retiring the version at the second barrier, then let the live attempt send. | Where that attempt sends, only the original approved value can match and the count stays at one. A suppressed or interrupted attempt preserves its no-effect or uncertain receipt without a fallback invocation. |

## Native pipe SQOS checks

Run the [authority channel table](contracts/authority.md#local-pipe-impersonation-boundary) against the actual installed local clients and server handlers on ARM64. Include both launch hops, native consent, participant, metadata bridge, outbound broker-to-render, fixed dispatch and fake receipt lookup. Check every runtime-selected alternative and fresh reconnect. Label each result with OS client direction and step category so a passing inbound check cannot cover an outbound client. Duplex replies inherit the opening connection's policy.

- For each role, confirm the client uses the explicit identification-only open. On the actual server handler's preface and representative command/effect frame, observe the Windows `TokenImpersonationLevel` result, the expected identity-match boolean and successful `RevertToSelf` before the request handler. Instrument the production gate, with fixtures for the actors and input. Record no token data, handle, raw SID or token privilege list. Verify a value-free native preface for every role and a fresh open with the same settings after reconnect. Observe the actual receive checks on the A dispatch and B render frames with synthetic values during their own flows.
- On each privileged role, use isolated, otherwise pin-matched fixture peers for a default open, an explicit overbroad open and an anonymous open. Force failed impersonation or an unreadable level and verify rejection before the request handler, with zero authorization, storage or delivery actions. Where a negative peer reaches token query, verify the real Windows level is rejected. Record any earlier OS denial separately. A failed revert must terminate its serving process without a receipt manufactured by the authentication thread. Exercise remote denial before any ready response.
- Confirm no privileged client sends its request or canary when a trusted endpoint fails the preface. Confirm no access token or token handle is serialized in either direction or shipped in diagnostics. A peer/PID match without the effective-token observation, or an unmeasured role, is incomplete.

## Leakage coverage

- Generate independent unpredictable canaries (at least 128 bits of entropy) inside the broker with a fixed ASCII representation. The broker compares internally or seeds only the authorized fake and renderer through the private test channels. The detector runs inside the trusted fixture boundary, uses in-memory forbidden variants, and emits path categories, coverage, counts and outcome only. Never write a canary, capture excerpt, deterministic hash, variant or extractor payload to an artifact. Run isolated positive controls for exact, encoded and screenshot/text-capable checks separately from the evidence of zero leakage. Partial strings in transformed error paths are checked using several disjoint canary substrings with unrelated-baseline controls.
- Check exact raw bytes and UTF-8/UTF-16LE/BE, common escaping and transformations from the actual tooling (JSON/Unicode escapes, URL encoding, hex, Base64 and Base64url), decoding serialized or compressed artifacts inside the trusted verifier as needed. Failure to inspect an applicable format leaves the gate incomplete. Include malformed/error/timeout inputs, rejected response echoes, and content crafted by the fake to test dropped fields. Counters never derive from caller success text.
- Inspect model/tool message wiring, chat/fixture transcript, CLI/MCP including JSON and error envelopes, Herdr terminal transcript/PTY/screen captures and exports, Workspace and execution result captures, Council artifacts, and outbound Plane payload observation. Pilot emits no Plane event, uses no live provider, and injects none of these bytes into any model. When a connector is absent and no payload can exist, verify isolation and zero outbound attempts with the fixture interceptor. A deterministic Node/native fixture or simulated model boundary must be reported as such.
- Inspect every pilot process and child argv, actual inherited environment, stdout/stderr, app/core/OS pilot event logs, tracing/telemetry sinks, crash/dump settings and crash survivors, pilot scratch, protected store files including database/WAL for plaintext, and related workspace/Git untracked, staged and tracked content and pilot commits. Verify writable paths and telemetry/egress for the fixture. Exclude unrelated personal data from collection. Store artifacts never carry plaintext. Do not create a dump of secret-bearing memory.
- From the participant or same-user decoy attempt to observe protected UI via ordinary accessibility, native capture and clipboard surfaces and to inject into the operator session. Verify no copy action, no leak in accessible metadata or screen sharing, no value-bearing screenshot; retain only probe booleans or counters. Verify the selected native control paints once using a comparator inside that surface. No video or screenshot of the live reveal is retained. Document protected-process and desktop prerequisites and mark any unobservable required surface incomplete.

## Evidence to publish

Use one redacted report per package/build with package digest, exact commit, OS build and ARM64 mode, Desktop/core/Council versions, provisioned security properties or failed preconditions, participant type and execution layers. Per case, include sequence of safe event names and opaque IDs, crash cut and disposition, independent invocation/effect/reveal deltas, reconciliation reference and leakage coverage/positive-control results. Include keyboard and safe accessibility inspection, channel-level effective SQOS results and the A-entry comparison booleans. Redacted supporting artifacts may include UI screenshots only with no value rendered. Log all skipped or blocked assertions clearly.

Record pure unit/fault simulations separately from live local Herdr with a deterministic fixture and from actual native OS controls. An ordinary repo suite pass only shows regressions for its exercised scope. A real harness, other platform, power-loss guarantee and real-value release each need distinct verification before any such claim. No real model or credential is required by this pilot.
